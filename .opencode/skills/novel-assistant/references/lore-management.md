# 设定管理参考

涵盖 5 种设定数据库操作能力：人物 / 势力 / 世界观设定完善 + 批量处理 + 一致性审计。

---

## 通用设定完善流程

人物、势力、世界观三种设定完善共享同一个四步流程，仅 `category` 字段和提取重点不同。

### 通用步骤
1. **Grounding**：`get_lore_snapshot` → 检查实体是否存在 → 存在则 `get_entry_details` 获取完整档案
2. **Reading**：`read_chapter_content` 读取指定范围章节
3. **Extraction**：比对章节内容与现有档案，找出未记录的新细节
4. **Safe Commit**：`propose_patch` → 展示 diff → 用户确认 → `commit_patch`（遵循 SKILL.md Propose-Commit 约定）

### 安全约束
- 单次任务严禁跨度超过 **15** 个章节
- 真理来源仅限 `get_entry_details` 和 `read_chapter_content` 返回的数据
- 严禁臆造设定

## 完善人物设定（设定完善助手 - 人物篇）

### 参数
- `character_name`（**必填**）：人物名称
- `volume`（默认：`1`）
- `start_chapter`（默认：`1`）
- `end_chapter`（默认：`5`，建议跨度不超过 10 章）

### 提取重点
外貌、具体能力、关键经历、人际关系

### propose_patch 格式
```json
{
  "lore_updates": [{
    "type": "update",
    "category": "characters",
    "name": "<character_name>",
    "content": "- 获得新武器（第5章）\n- 受伤：左臂（第6章）",
    "metadata": { "status": "受伤" },
    "source": "vol<V>/Chapter.<start>-Chapter.<end>"
  }]
}
```

## 完善势力设定（设定完善助手 - 势力篇）

### 参数
- `faction_name`（**必填**）：势力名称（如"组织A"、"组织B"）
- `volume`（默认：`1`）
- `start_chapter`（默认：`1`）
- `end_chapter`（默认：`5`，建议跨度不超过 15 章）

### 提取重点
1. **组织结构**：核心成员、职位层级、部门划分
2. **外交关系**：与其他势力的结盟或敌对状态变化
3. **重要行动**：策划或执行的大事件
4. **据点与资源**：基地位置、特殊科技或武装力量

### propose_patch 格式
category: `"factions"`，其余同人物格式。

---

## 完善世界观设定（设定完善助手 - 世界观篇）

### 参数
- `concept_name`（**必填**）：概念名称（如"核心设定A"、"核心设定B"）
- `volume`（默认：`1`）
- `start_chapter`（默认：`1`）
- `end_chapter`（默认：`5`，建议跨度不超过 15 章）

### 提取重点
1. **起源与历史**：来历、传说
2. **规则与机制**：运作方式、限制条件
3. **视觉表现**：颜色、光影、声音
4. **影响范围**：对世界或人物的具体影响

### propose_patch 格式
category: `"worldview"`，其余同人物格式。

---

## 批量设定完善（设定完善助手 - 批量版）

### 参数
- `character_list`（可选）：人物列表，逗号分隔
- `faction_list`（可选）：势力列表，逗号分隔
- `volume`（默认：`1`）, `start_chapter`（默认：`1`）, `end_chapter`（默认：`5`）

至少提供 character_list 或 faction_list 之一。

### 安全警告
由于注意力机制在长上下文中会衰减，建议每次只处理 **3-5** 个条目。

### 执行步骤
1. 解析列表，拆分为单独条目
2. **依次处理每个人物**（若有 character_list）：
   - 按「完善人物设定」的完整流程执行
   - 每处理完一个，等待用户确认后再继续下一个
3. **依次处理每个势力**（若有 faction_list）：
   - 按「完善势力设定」的完整流程执行
   - 同样等待用户确认后继续
4. 全部完成后输出简报：
   - 成功完善的条目数量
   - 每个条目主要补充了哪些设定
   - 发现的任何潜在冲突

## 设定一致性审计（设定审计师 / Consistency Auditor）

对设定数据库进行全面交叉检查，找出矛盾、冗余和信息空白。

### 参数
- `category`（默认：`all`）：审计范围（`characters` / `factions` / `worldview` / `items` / `all`）
- `deep_check`（默认：`false`）：是否对照章节内容深度核验（耗时较长）
- `volume`（默认：`1`）：deep_check 时使用的卷号

### 审计目标
1. **内部矛盾**：同一实体在不同档案中的矛盾描述
2. **设定空白**：重要条目缺少关键信息
3. **孤立条目**：没有交叉引用关系的实体
4. **命名冲突**：相同或相似名称指代不同实体

### 执行步骤

1. **全库快照**：`get_lore_snapshot`，按 category 参数决定审计范围
2. **逐条深读**：对每个条目调用 `get_entry_details`
3. **交叉比对**：
   - 提取每个条目中提到的其他实体名称
   - `search_lore(keyword=...)` 检索这些实体
   - 比对两个档案中对同一关系/属性的描述是否一致
   - 特别检查：人物→势力关联、势力→关键人物关联、世界观规则一致性
4. **深度核验**（deep_check=true 时）：
   - 按优先级排列需核验条目（主角 > 重要配角 > 主要势力 > 关键概念）
   - 对每个条目抽取 3-5 个关键章节与档案比对
   - 记录正文与档案不一致之处
5. **输出审计报告**：

```markdown
# 设定一致性审计报告

## 📊 审计摘要
- 总条目数：N
- 发现问题：X 个（严重/中等/轻微）

## 🔴 严重矛盾
- [条目A] vs [条目B]: 关于XX的描述存在直接冲突
  - A档案：...
  - B档案：...
  - 建议：...

## 🟡 设定空白
- [条目名]: 缺少 [外貌/能力/背景] 信息

## 🟢 轻微问题
（不影响逻辑但需完善的细节）

## ✅ 无问题条目
```

6. **建议优先级**：按重要性排序，标注哪些需立即修正、哪些可后续补全
